# 成品级前端交付守则
界面是交付给最终用户的产品表面，不是向需求方证明完成度的实现报告。本守则约束 Agent 产出的所有用户可见前端（页面、组件、原型、邮件模板），交付标准为可直接上线。
## 核心模型：三个信息通道
界面噪声的根因是混淆读者。一次交付中存在三个通道，各自面向不同读者：
| 通道 | 读者 | 承载内容 |
|---|---|---|
| 界面 | 最终用户 | 完成操作所需的最短文字：标签、按钮、状态、必要提示 |
| 源码注释 | 后续维护者 | 复杂逻辑、契约、TODO——写在代码里，不渲染 |
| 交付消息 | 提出需求的人 | 实现说明、技术决策、使用指引、已知限制 |
判定规则：文字进入界面前先做删除检验——删掉它，用户完成操作是否受阻。受阻则保留；不受阻则移入源码注释或交付消息，或直接删除。
## 一、界面噪声（禁用）
1. **需求复述**：把用户要求或要点列表搬进页面，如三张卡片写着「实时协作」「多端同步」「版本回溯」。
2. **功能解释与自述**：以任何人称说明实现（「本页面将调用接口获取数据」「此处展示智能分析结果」），或 AI 署名角标（「由 AI 生成」）。
3. **注释外漏**：TODO、「待实现」、说明性文字出现在渲染结果里；空状态写「功能开发中，敬请期待」。
4. **占位标签**：Lorem ipsum、「示例数据」「测试内容」字样贴在界面上；示例内容不具备业务语义。
5. **调试可见**：state 值、JSON、报错信息渲染进 DOM。
6. **教学浮层**：分步引导遮盖核心界面，「点击此处开始」式箭头标注。
7. **摆件交互**：点击无响应的按钮、指向 # 的链接、提交无反馈的表单。
8. **装饰堆砌**：无信息量的 emoji 标题、渐变背景、发光阴影、为填充空间而存在的图标。
## 二、成品标准
- **文案**：按产品文案写。动词开头、短、具体：按钮是「导出报表」，不是「点击此处进行报表导出」。
- **数据**：无真实数据源时，填充语义成立的示例数据——人名符合真实姓名格式、数值落在业务合理区间、字段结构贴近真实接口。示例数据不带「示例」标签，除非用户要求演示场景。
- **状态完整**：空、加载、错误、成功四态覆盖。空态给出路（「暂无项目」旁放新建入口），不放解释。
- **交互闭环**：可交互元素接通行为与反馈；表单有校验与提交结果；未实现的入口不渲染，而非渲染成灰色摆设。
- **视觉克制**：一个主色、一个中性色阶、一套字体栈；层级来自间距、字重、字号，不来自彩色渐变；间距使用统一刻度（4/8px）。
- **布局可用**：不写死超出常见视口的宽度；可交互元素有可见的 hover/focus 态；使用语义化标签。
## 三、交付检验
三项检验全部通过才可交付：
1. **删除检验**：逐句检查界面文字，删除后不影响用户操作的，全部移除。
2. **生产检验**：设想页面部署在真实域名、陌生用户首次打开。此时显得突兀的元素——说明、标签、摆件按钮——即噪声。
3. **对照检验**：同类成熟产品的对应界面（表单对 Stripe、列表对 Linear、协作对飞书）不长这样的，给出保留理由，否则对齐。
## 四、边界与例外
- 实现说明与待办写在交付消息；复杂逻辑注释写在源码对应位置。两者都不进界面。
- 清理既有界面噪声时直接删除，不注释保留、不折叠隐藏。
- 用户明确要求教学页、演示标注、原型标注时，按需求交付，不受本守则限制。
- 项目已有视觉规范（设计稿、品牌色、组件库）时遵循规范，本守则只约束其中未覆盖的噪声问题。
## 交付前自查
- [ ] 界面内无需求原词、功能解释、「示例/Demo/待实现」字样？
- [ ] 每个按钮、链接、表单接通了行为与反馈？
- [ ] 空/加载/错误/成功四态处理完毕，空态给出路？
- [ ] 示例数据语义成立、结构贴近真实接口？
- [ ] 删除检验逐句执行过？

## 附录：界面文字对照示例
| 场景 | 噪声写法 | 成品写法 |
|---|---|---|
| 需求复述 | 首页三卡片：实时协作 / 多端同步 / 版本回溯 | 直接呈现协作画布，功能在导航与使用中体现 |
| 功能解释 | 此区域将调用 API 加载待办并智能排序 | 待办列表本体 + 排序结果 |
| 空态 | 这里空空如也，功能开发中~ | 输入框 + 「添加第一个任务」 |
| 未实现入口 | 置灰的分页按钮，旁注 TODO: 下一页 | 不渲染该按钮 |
| 按钮文案 | 点击此处提交您的表单信息 | 提交 |
| 首次进入 | 欢迎使用！本系统分为三大模块，请跟随引导…… | 直接进入核心界面 |
