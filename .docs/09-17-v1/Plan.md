## 1. 背景与目标

Capsa 作为部署于个人 VPS 的私人长期记忆服务，最初将 Web 端设计为与 Agent 权限对称的访问台。但在单人实际使用场景中，各类客户端与 Agent 仅通过协议访问对应权限的记忆，而 Web 端则应当作为服务拥有者（个人管理员）的全局控制中心。

本次改造旨在将 Web 管理台收敛为**全权限单管理员面板**，并补齐**分类（Group）生命周期管理**能力，具体目标包括：

1. **鉴权收敛为单管理员模式**：
   - 支持管理员专属凭据（通配读写凭据 `*:rw` Key 或管理级环境变量令牌）登录。
   - 确立清晰严密的后端鉴权边界（方案 A）：Web API（`/api`）入口网关统一强制核验管理员通配凭据，直接拒绝任何非管理员普通凭据（返回 403 FORBIDDEN），杜绝绕过前端调用。
   - 登录后即享有全库所有分类与记忆的完全管理权限（浏览、检索、新建、编辑、软删除、时效复核与回收站恢复）。
2. **打通 MCP 工具层的管理员写权限**：
   - 统一收敛权限判定核心契约，使 MCP 读写工具集与 Web API 同步支持通配读写凭据。
3. **分类生命周期管理**：
   - 后端新增分类原子创建与就地编辑接口，杜绝并发竞态，且保证 SQLite 外键安全（唯一标识创建后严格不可变）。
   - 前端新增轻量分类管理界面，支持分类快速创建与编辑，并与工作台分组筛选及创建抽屉实时联动。
4. **架构约束守正**：
   - 坚决不引入独立用户表、多角色 RBAC、密码管理或 Cookie/Session 状态，保持既有 Bearer 令牌极简模式。
   - 保持 Web 统一信封响应契约，补齐 Python 单元测试（含 MCP 通配写、直接绕过前端防线拦截等关键边界）与端到端回归测试，同步维护项目文档与说明文件。

## 3. 架构决策与设计原则

- **清晰明确的单管理员后端边界（方案 A）**：
  坚决避免“前端拦截、后端放行”的双重标准。Capsa 中 `/mcp` 负责面向 Agent 的协议读写，而 `/api` 是专属于 Web 管理台的 REST 接口。在 `/api` 的入口网关层强制执行管理员凭据校验（具备 `*:rw` 权限），任何非管理员 Token 无论以何种方式发起请求，一律被网关拦截为 403 FORBIDDEN。
- **权限判定单一事实来源（避免规则散落）**：
  提取统一纯函数 `permission_for(grants, group)`，统一判定具体分组权限与 `*:rw` 通配兜底逻辑。DAL、MCP 服务层与 Web API 均基于该函数获取有效权限，彻底消除“读取放行、创建放行、更新或 MCP 工具层遗漏”的不对称缺陷。
- **管理级环境变量令牌的最小规范**：
  - 仅在环境变量非空且去空后有值时启用，未配置或空串时静默不启用。
  - 每次请求只读环境读取，进程更新即时生效，无任何数据库依赖与 CLI 维护负担。
  - 身份信息固定映射为 `id="admin"`、`name="Admin"`、`grants={"*": "rw"}`。
  - 轮换策略极简：更新环境变量并重启服务。
- **SQLite 外键参照安全与原子写入**：
  - 记忆表以外键关联分类表的唯一标识（slug）。分类唯一标识一旦创建即不可变更，仅允许修改分类的展示名称与描述信息。
  - 存储层修改分类创建逻辑，返回显式的插入影响结果，根治并发冲突时先查后插的 TOCTOU 竞态。
- **文档事实来源全量对齐**：
  维护更新不仅覆盖 `.docs/Project.md`，同时修正根目录 `README.md` 中关于“Web 权限对称”与“分组维护仅在 CLI”的陈旧描述。

## 4. 风险评估与应对策略

| 风险点 | 影响评估 | 应对策略 |
|--------|----------|----------|
| MCP 适配层仍有漏网的硬编码分组判定 | 高 | 建立统一的 `permission_for` 契约，并在测试阶段增加针对 MCP `memory_save`、`memory_update`、`memory_forget` 携带 `*:rw` 凭据的专项测试用例 |
| 非管理员凭据绕过浏览器直接调用 REST API | 高 | 在 ASGI 守卫层全局校验管理员权限，未通过者直接返回 403，并补充对应的 HTTP 客户端直接绕过断言 |
| 环境变量误设为空导致凭据验证异常 | 中 | 在读取环境变量时使用 `.strip()` 并严格判断布尔真值，空字符串均视为未启用该环境变量 |
| 分类并发创建导致静默成功却未入库 | 中 | 改造存储层底层插入方法返回影响行数标识，通过原子写入感知唯一性约束冲突并转化为 422 错误 |
