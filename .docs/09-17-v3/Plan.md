## 1. 背景与目标

Capsa 在 Phase 5 中将 Web 管理台收敛为全权限单管理员面板，并引入了分类创建与就地编辑能力。然而，在分类与凭据的日常运维生命周期中，仍存在两个关键操作断点：
1. **分类删除断点**：分类一经创建无法删除，即使分类下已无任何记忆，管理员也无法清理废弃分类。
2. **凭据管理断点**：Key 签发、吊销与凭据审阅仍停留在宿主机 CLI 阶段。管理员在 Web 端无法获知当前活跃 Agent 的凭据分布，也无法在界面上为新 Agent（如 Cursor、Claude Desktop 等）安全签发限制权限的分组 Key。

本次增强旨在补齐上述断点，实现以下目标：
- **分类生命周期闭环**：Web 管理台支持安全删除分类，在存储层以单一原子契约校验关联记忆（含回收站），杜绝孤儿记忆、外键破坏与并发 TOCTOU 竞态。
- **凭据深度管理与可视化签发**：在 Web 管理台提供一站式 Key 管理面板，支持查看数据库全量 Key 状态（有效/已吊销）、最后活跃时间、细粒度分组权限分布；支持在线安全签发新 Key（单次明文披露与一键复制）；支持就地吊销与安全清理已废弃 Key，防范管理员自锁误操作，并理清环境变量虚拟凭据边界。
- **架构约束守正**：维持单管理员极简架构，不引入用户表、会话状态或复杂 RBAC；所有 API 守在统一管理员网关之后；保持统一信封与错误码规范，避免交互与安全防御过度膨胀。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 分类删除原子化契约 | 存储层原子执行“检查+删除” | 消除 Web 层先查后删的 TOCTOU 竞态，确保外键冲突不逃逸为 500 异常 | Web 业务层拼装 count 与 delete（存在并发竞态且易导致未捕获的数据库异常） |
| Key 状态校验与删除契约 | 存储层原子提供 delete_revoked_key | 保持既有 get_key 契约与测试不变；状态约束下沉 DAL 保证仅已吊销 Key 可物理删除 | 修改现有 get_key 破坏既有契约；或 Web 层两次查询引发竞态 |
| 环境变量虚拟管理员身份边界 | 不落库、不进 Key 列表、不可作为操作目标 | CAPSA_ADMIN_TOKEN 每次从环境读取，服务无状态管理；自锁规则统一拦截针对自身的操作 | 伪造入库或允许管理接口操作（破坏无状态与单点事实来源） |
| 分类删除后的悬空 Key Scope | 仅允许删空分类，保留历史 Key 中的 Scope | 记忆库无记忆即无越权风险；重建同名 slug 时权限无缝衔接；无级联重写 JSON 负担 | 级联清洗所有 Key 的 JSON（逻辑复杂且易产生意外数据变更） |
| 交互层防护粒度 | 保持轻量克制，单个显式确认按钮 | 符合个人 VPS 工具定位，避免防御过度膨胀 | 增加离开拦截 (beforeunload)、焦点锁定或剪贴板轮询（过度防御且干扰体验） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 并发写入导致分类删除违反外键约束 | 🔴 高 | DAL 在单一函数事务内完成状态检查与删除，返回明确状态码，杜绝未处理异常 |
| 管理员自吊销导致会话立即失效锁死 | 🔴 高 | 后端吊销与删除接口对比 claims 的 key_id 与目标 id，命中直接阻断并返回 422；前端禁用针对自身的破坏性操作 |
| 环境变量管理员作为操作目标产生脏数据 | 🟡 中 | 目标 id 为 admin 时统一拦截为 422 提示（环境变量凭据通过改值重启轮换） |
| 前端自定义权限全选“无权限”提交 422 | 🟢 低 | 前端在表单层添加校验，自定义模式下至少勾选一个有效分组权限，否则禁用提交按钮 |
