## 1. 背景与目标

当前记忆检索服务仅支持在标题、标签和核心摘要层进行匹配。对于特定代码片段、配置细节或隐式参数，若未被提取至标题与摘要中，Agent 无法通过关键词有效召回，造成深层记忆盲区。此外，交付给 Agent 的 MCP 工具体系中存在高频重复的微操指引（如刻板规约三步调用流程、负向诫勉等），增加了上下文噪声，制约了 Agent 的自主规划与推理空间。

本次改动旨在达成以下目标：
- 为 MCP `memory_search` 增加可选的正文检索参数，默认关闭以保护轻量环境的内存开销；仅在 `query` 非空且显式开启时加载正文，空 query 浏览杜绝正文全量加载；
- 实施非对称低权重打分机制：在同等置顶与有效状态下，元数据命中（标题 4、标签 2、摘要 1）基础分严格压倒正文命中（单词元 0.2，上限 0.8）；同关键词下标题命中条目排序严格高于正文命中条目；
- 明确系统边界：按需正文检索仅面向 MCP Agent 端点，Web 管理台与 CLI review 保持元数据检索能力，默认不暴露也不查正文；
- 重构全量 MCP 工具的描述、参数注解与披露契约，剔除刻板微操指令，保留中立、客观的渐进披露边界说明（检索取元数据不显式返正文、peek 取摘要、read 取正文），实现高信噪比规范契约；
- 确保既有 184 个测试用例 100% 通过，并补全正文检索与排序权重的验收测试。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 正文加载策略 | 按需条件动态查询（方案 A） | 默认状态下不查正文字段；且仅在 query 非空且 include_body=True 时查正文，避免空 query 浏览扫描大文本，保护 VPS 资源 | 启动时内存驻留正文（占用内存过大）、空 query 也加载正文（浪费内存） |
| 检索匹配与打分权重 | 非对称极低权重打分（方案 C） | 标题（4分）、标签（2分）、摘要（1分），正文命中仅赋予 0.2 分（上限 0.8 分），保证同等修正状态下元数据基础分严格高于正文得分 | 扩大基础分倍数（会破坏已有断言契约）、正文等权打分（正文词频过高导致排序反转） |
| 检索能力边界 | 仅 MCP 工具暴露 include_body | 兜底检索是为自主 Agent 在细节召回失败时的推理补偿；Web 管理台面向人工审阅，CLI review 属于确定性检查，无兜底正文扫描需求，避免不必要的调用面扩散 | Web/CLI 同步暴露该参数（缺乏实际使用场景，增加接口复杂度） |
| 提示词风格规范 | 去除刻板微操，保留中立渐进披露契约 | 剔除“不要一次性读取正文”等训诫指令，保留“检索返回元数据不含正文、peek 看摘要、read 读正文”的中立契约，兼顾 Agent 自主性与披露边界认知 | 完全移除三层语义（易致 Agent 误以为 search 已返回正文） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| 空 query 传入 include_body=True 导致全库正文加载 | 🟡 中 | MCP 工具层做收敛守卫：`load_body = bool(include_body and query and query.strip())`，空 query 浏览坚决不加载正文 |
| 正文词频过高导致正文命中条目逆袭标题条目 | 🟡 中 | 对正文命中实施非对称低权重（0.2）且设置得分上限（0.8），同修饰条件下标题（4）与摘要（1）始终高于正文 |
| 调整结果格式导致端到端测试正则断言失败 | 🟡 中 | 严格保持 `> 下一步: memory_peek(ids=[...])` 等测试依赖格式，仅精简冗余话术，保证 184 个用例全部通过 |
