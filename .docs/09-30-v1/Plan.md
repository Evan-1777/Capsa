# Plan：兼容 URL 查询参数传递访问凭据

**状态**：DONE  
**日期**：2026-09-30  
**版本**：v1.1  
**回归测试结论**：全量回归测试 215 项（原 209 项 + 新增 6 项 URL 查询参数鉴权测试）100% PASSED，零回归。

## 1. 背景与目标

当前 Capsa 仅支持通过 HTTP `Authorization: Bearer <token>` 请求头传递凭据。在尝试通过 Claude Web 端自定义连接器（Custom Connector）或类似无自定义 Header 配置能力的客户端接入 Capsa MCP 服务时，客户端无法附加请求头；同时 Capsa 作为面向个人 VPS 的轻量私人记忆服务，未实现复杂的 OAuth 2.0 授权码流，导致此类客户端探测时因收到 401 报错而无法完成连接。

本次演进旨在为服务端增加 URL 查询参数凭据接入能力，实现以下目标：

- **服务端具备查询参数凭据能力**：允许客户端在请求地址中携带 `token`（或兼容 RFC 6750 的 `access_token`）参数传递访问令牌，平滑接入 Claude Web 端自定义连接器等仅支持端点 URL 配置的客户端。
- **结构化归位与无损衔接**：在系统 HTTP 接入边界处以极简 ASGI 中间件将查询参数令牌适配为标准 Bearer 凭据，下游 FastMCP 框架、Web REST API、DAL 数据访问层及现有鉴权/授权逻辑（Key 作用域、撤销即时生效、管理员通配、使用时间更新）零改动复用。
- **守正克制与向后兼容**：既有 HTTP 请求头鉴权机制不受任何影响，当请求头与 URL 查询参数同时存在时，严格以 HTTP 请求头为单一权威来源；零新增外部依赖，维持项目轻量与低复杂度定位。
- **自动化测试保证**：提供覆盖 MCP 端点与 Web API 端点的自动化测试，确保正常链路、鉴权优先级与错误边界（含非 ASCII 字符防护）均得到机械化验证；部署后支持真实客户端手工联调验收。

## 3. 架构决策

| 决策项 | 选择 | 理由 | 替代方案（为何不选） |
|--------|------|------|----------------------|
| 凭据接入位置 | ASGI 根应用层全局中间件装配（有意决策） | 溯源根因、最短差分与模型对称。在数据流源头将 URL query 凭据映射为标准 ASGI Authorization 头，免除针对 `/mcp` 路径的特判分支，下游 FastMCP `RequireAuthMiddleware`、`BearerAuthBackend` 与 Web API 网关自然复用，零修改第三方依赖与内部业务逻辑 | 在 FastMCP 工具层或各个 API 路由分别取 query（打补丁式修改，破坏 MCP 传输层与协议层分工，且无法绕过 FastMCP 前置的 401 拦截）；或在中间件层写死路径判断（增加耦合与概念开销） |
| 依赖与实现选型 | Python 标准库 `urllib.parse` | 极简自洽。标准库开箱即用且高效，无需增加新外部依赖 | 引入额外的中间件库或复杂解析库（违背轻量定位与 SCOPE 原则） |
| 凭据冲突仲裁 | Header 优先（Header 存在时不解析 Query 参数） | 契约明确、防御混淆。遵循标准 HTTP 鉴权惯例，避免请求头与 URL 参数冲突引发的安全歧义 | Query 覆盖 Header（易导致代理缓存或日志中的 URL 参数意外覆盖显式传入的安全凭据） |
| 查询参数命名支持 | 首选 `token`，兼容 `access_token` | 语义直观且对齐标准。`token` 满足用户直觉与简易配置习惯，`access_token` 兼容 RFC 6750 §2.3 规范 | 引入可配置参数名（当前无多场景需求，违背 YAGNI 原则） |
| 非 ASCII 字符处理 | `token.isascii()` 校验，非 ASCII 不注入透传 | 根因防御。避免在 latin-1 编码阶段抛出 `UnicodeEncodeError` 逃出中间件导致 500 异常，使其自然落入下游 401 凭据缺失/无效逻辑 | 捕获异常后手写 401 响应（在中间件层重新制造统一信封与 fastmcp 双分支响应，冗余度高） |

## 4. 风险清单

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| URL 查询参数落入反代访问日志、uvicorn 日志或浏览器历史 | 🟡 中 | 明确披露方案固有代价。在 `Project.md` 与配置指南中提示反代日志脱敏建议；强烈建议用户为 Claude Web 等连接器签发专用低权限分组 Key（如仅授予 `proj:rw`），禁止复用通配管理级凭据 |
| 非 ASCII 畸形字符引发中间件内部编码异常导致 500 | 🟢 低 | 中间件增加 `token.isascii()` 前置判断，含非 ASCII 字符时直接跳过代客注入，交由下游统一返回 401 |
| 影响现有依赖 Bearer 请求头的 MCP 客户端或 Web 管理台 | 🟢 低 | 中间件采用守卫式判定，只要请求头中存在 `authorization` 立即短路放行，保证既有客户端零行为变动 |
